## What changed since the last version of this doc

The previous version of this report (commit `80aa57c`) was independently
audited in `planning/ADVERSARIAL-REVIEW.md` (2026-09-04, read-only pass).
That review found real bugs the report had missed or mis-stated — a
`*-home.png` screenshot bug that made every "home screen" screenshot
actually show onboarding, tutor-mode chips that didn't update the UI,
duplicated voice captions, an unreadable-contrast passage in some voice
states, a clipped push-to-talk ring, and several smaller items (full list
in that file's §1/§2).

This version reflects a subsequent fix pass (lane B of two parallel fix
lanes; lane A handled server hardening, settings wiring, and the licences
screen) plus fresh evidence gathered tonight and saved to
`docs/evidence/*.log`. Where the review's findings are now fixed, this
table says so and cites the fix; where they aren't, it says that too. The
review's own §3 table (its recommended status changes) is the baseline for
every row below — nothing here re-litigates its reading of the prior code,
only updates it against what changed.

Evidence paths are relative to the repo root. `pnpm check` tail is at the
bottom of this doc; the full tail plus a live-voice e2e log and a
server-smoke log are saved in `docs/evidence/`.

## Design-drift fixes this pass (`planning/design/DESIGN.md`)

The adversarial review's §2 "design-spec drift" list flagged several places
the shipped app didn't match `DESIGN.md`. Fixed this pass, all verified by
reading the current code (and, where noted, live in the Browser pane):

- **Completion view's arrow was the literal `↓` character**, not the
  spec'd "hand-drawn arrow — single 1.5px ink SVG path with slight wobble".
  Replaced with `HandDrawnArrowGlyph` (`apps/client/src/ui/Glyphs.tsx`): a
  single stroked `<Path>` whose shaft bows slightly rather than running
  straight, ending in an asymmetric two-stroke arrowhead. Used in
  `app/reader/[bookId].tsx`'s `CompletionView`.
- **Desktop onboarding rendered inside the tabs sidebar shell** —
  `1024-home.png`/`1440-home.png` used to show the "Pour toi / Bibliothèque
  / Vocabulaire" nav next to the onboarding wizard, because `Shell` always
  renders its desktop `Sidebar` regardless of route. Added a `sidebar`
  prop to `Shell` (default `true`, unchanged for every other caller — book
  detail, profile, review, search, licences, settings); `onboarding/
languages.tsx` and `onboarding/level.tsx` now pass `sidebar={false}`, so
  onboarding stays a plain canvas screen at every width. Also added the
  same already-onboarded redirect guard to `onboarding/level.tsx` that
  `onboarding/languages.tsx` had (commit `b63a5f8`) — no "reach onboarding
  again" path exists in settings, so none was added (nothing to preserve).
- **"Signaler" in the reader opened a `mailto:` to a domain that doesn't
  resolve to a Sotto inbox** (`feedback@sotto.app`), so reports went
  nowhere. Now opens
  `https://github.com/nturl/sotto/issues/new?template=bug_report.md` via
  `Linking.openURL` (`app/reader/[bookId].tsx`).

## Fragility fixes this pass (not spec drift, but named in the review's §2)

- **`flatTokens.indexOf(token)` ran per token per render** in the reader's
  narration hot path (`app/reader/[bookId].tsx`'s `ReaderBlock`) — narration
  updates `positionMs` roughly every 60ms, so a long chapter did an O(n²)
  scan per frame. Replaced with a `tokenIndexById: Map<string, number>`
  built once per chapter (`useMemo` keyed on the chapter's token list) and
  passed down instead of the raw token array.
- **Completion fired on a scroll-fraction heuristic that could fire early**
  — see row 16 above for the fix (last-block-visibility gate instead of a
  scroll-percentage threshold).

## Found and fixed this pass — the word→tokenId bug (was row 9's headline finding)

The prior version of this report's headline "found, not fixed" bug was a
voice-triggered `save_vocabulary`/`set_reading_position` call landing on the
wrong word (asked to save "cigarra", the store ended up with "verano"
instead, twice). That report blamed `packages/core/src/prompt.ts`'s
`buildSystemInstruction`. The adversarial review pointed out that diagnosis
was wrong on every count: no function of that name exists in that file (it
exports `buildTutorInstruction`, not `buildSystemInstruction`); it is dead
code used by nothing but its own test (`grep buildTutorInstruction` hits
only `packages/core/src/prompt.ts` and `prompt.test.ts`); and the actual
live path is a different file entirely, `apps/server/src/voice/prompt.ts`,
whose own `buildTutorInstruction` **does** render a word→tokenId map
(`renderSentence`). The real fix (commit `da695d3`, landed before this
pass, by a session spawned specifically for it) added that word→tokenId
map to `apps/server/src/voice/prompt.ts`'s live prompt renderer and
tightened `apps/client/src/voice/toolContext.ts`'s `resolveWordToken` to
re-resolve a stated word against the nearest matching token rather than
trusting a numerically-guessed id. Re-ran the live e2e
tonight to confirm: `docs/evidence/voice-live-2026-09-04.log` — the
vocabulary store ends with `["verano","cigarra"]` (a correct "cigarra" save
plus the harmless earlier "verano" from the same run's other assertions),
not "verano" in place of "cigarra". `packages/core/src/prompt.ts` itself
was left as-is this pass (deleting it, plus its test, is a clean follow-up
but wasn't in this lane's scope).
