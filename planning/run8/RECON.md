## 7. Test conventions

- **There is no `vitest.config.*` anywhere in the repo**. `pnpm test` = bare `vitest run` at the root (`package.json:20`) and per-package (`apps/client/package.json` `"test": "vitest run"`). Vitest 3.2.4 is a root devDependency.
- Consequence, documented in-repo twice (`src/ui/navRows.ts:5-12`, `src/ui/railView.ts:1-8`): **any module importing `react-native`, even transitively, fails to parse** under plain `vitest run` (Flow syntax). So there is **no component-render testing at all**.
- The pattern is: extract the decision into a RN-free pure module, test that. `railView.ts` ← `Rail.tsx`; `navRows.ts` ← `TabBar.tsx`/`Sidebar.tsx`. Test files sit next to the source: `src/ui/Rail.test.ts` (imports `./railView` and a hand-built `LibraryBook` literal, lines 1-22), `TabBar.test.ts` (imports `./navRows`, asserts row names/order), `Sidebar.test.ts`, `data.test.ts`, `notFoundLinks.test.ts`, `reader/selection.test.ts`, `reader/resolveWordPlayback.test.ts`. Style: `describe`/`it`/`expect` from `vitest`, `toEqual` on plain objects.

## 9. `apps/client/scripts/i18n-add.mjs`

Adds/updates strings in **every** catalog in one atomic synchronous pass. Two usages:
```
node apps/client/scripts/i18n-add.mjs '{"voice.retry":{"en":"Try again","fr":"Réessayer"}}'
node apps/client/scripts/i18n-add.mjs path/to/strings.json
```
Every key is written to all nine catalogs; a missing locale falls back to the English value so `pnpm content:validate`'s parity check stays green. Each key **requires** an `en` string or the script exits 2. New keys append at the end; existing keys are overwritten only for the locales given.
